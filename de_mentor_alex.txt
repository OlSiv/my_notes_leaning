Обнови main и создай ветку задачи - 
Переключись на main, получи последние изменения и создай отдельную ветку. Начни имя с ключа Jira: это связывает код с задачей и упрощает поиск истории.
- Не выполняй учебную работу прямо в main.
- Одна ветка должна решать одну задачу.
- Перед созданием следующей ветки снова обнови main.

--
git checkout main
git pull
git checkout -b DEIN-7809-short-title
git branch --show-current
----



Проверь содержимое и изменения - 
Открой созданный файл, выполни или проверь решение и сохрани его. 
Затем в терминале посмотри git status и git diff. 
В diff должны быть только изменения текущей задачи.
- Красные строки удалены, зелёные добавлены.
- Если видишь случайный файл, не добавляй его в commit и при необходимости внеси в .gitignore.
- Исправь форматирование до фиксации истории.

--
git status
git diff
----



Добавь файлы и создай осмысленный commit -
Добавь только проверенные файлы, создай commit с ключом задачи и коротким описанием результата. После commit снова выполни git status — рабочее дерево должно быть чистым.
- Не используй сообщения «fix», «work» или «final» без контекста.
- Ключ DEIN-47 в начале связывает commit с Jira.
- Если забыл файл, добавь отдельный commit; не переписывай общую историю без необходимости.

--
git add path/to/file.sql
git commit -m "DEIN-47 add customer report query"
git status
----



Отправь ветку в Gitea -
При первом push укажи upstream. После выполнения команда выведет ссылку на создание merge request. Обнови страницу репозитория Gitea и проверь, что ветка появилась.
- Push не переносит ветку в main и не завершает задачу.
- Следующие изменения в этой ветке отправляются обычным git push.
- Если push отклонён, прочитай сообщение: чаще всего требуется авторизация или обновление удалённой ветки.

--
git push -u origin DEIN-47-short-title
----



Создай merge request в main -
Нажми New Pull Request или ссылку после push. Проверь направление: source — твоя ветка, target — main. В заголовке укажи ключ и результат, в описании напиши что сделано, как проверено и добавь ссылку на Jira.
- Не меняй target на чужую рабочую ветку.
- Описание должно позволить повторить проверку без догадок.
- Перед созданием ещё раз просмотри список изменённых файлов.



Проверь вкладки MR и отправь на review -
Открой Conversation, Commits и Files changed. Убедись, что в MR нет чужих commit и лишних файлов, затем назначь ментора reviewer и переведи задачу Jira в Review, добавив ссылку на MR.
- Conversation хранит общее обсуждение, Files changed — комментарии к конкретным строкам.
- Если diff неожиданно большой, не отправляй MR до выяснения причины.
- Один открытый MR обновляется всеми последующими push в эту же ветку.



Исправь комментарии в той же ветке -
Прочитай каждый комментарий, внеси изменения локально, повтори проверку, создай новый commit и выполни git push. Новый MR создавать не нужно: существующий обновится автоматически.
- Не отмечай обсуждение решённым, пока исправление не отправлено.
- Если с комментарием не согласен, объясни решение аргументированно в ветке обсуждения.
- После push ответь reviewer, что именно исправлено.

--
git status
git add path/to/file.sql
git commit -m "DEIN-47 address review comments"
git push
----



Заверши задачу только после принятия -
После одобрения и слияния MR проверь результат в main. Добавь финальный комментарий в Jira со ссылкой на MR и способом проверки, затем переведи карточку в Done. Локально вернись в main и обнови репозиторий.
- Done означает принятый результат, а не просто отправленный push.
- Если MR требует правок, задача остаётся в Review или возвращается в In Progress.
- Удалённую рабочую ветку можно удалить после merge, если это принято в проекте.

--

Начни клонирование в VS Code
Клонирование — загрузка проекта с Gitea на компьютер. Делается один раз; дальше ты открываешь уже загруженную папку.

1 - Найди команду Clone
В VS Code нажми Ctrl+Shift+P. Напиши "Git: Clone" и выбери эту команду.

2 - Вставь ссылку
Вставь скопированную HTTPS-ссылку своего проекта и нажми Enter. Clone from GitHub для учебной Gitea выбирать не нужно.



07 -

Выбери папку и открой проект
Например, создай в «Документах» папку DE-course и выбери её. VS Code сам создаст внутри папку <твой_логин>-repo.

Уже загруженный по HTTPS проект открывай через File → Open Folder. Если вход снова отклонён после проверки логина и пароля Gitea, обратись к Куратору.

1 - Выбери место
Нажми Select as Repository Destination (в некоторых версиях Select Repository Location) / «Выбрать расположение репозитория». Выбирай отдельную папку для учебных проектов.

2 - Войди, если появится запрос
Git может попросить Username и Password: введи учебный логин и пароль от Gitea. Если запроса нет, данные уже сохранены. Вход в Gitea в браузере не заменяет этот запрос Git.

3 - Открой проект
Дождись загрузки и нажми Open / «Открыть» в уведомлении VS Code. Слева появятся файлы, внизу слева — main.



08 - 

Укажи автора коммитов
Коммит — сохранённое изменение в истории Git. Один раз укажи имя и почту, чтобы Git подписывал твои коммиты. Это данные автора, а не пароль.

Если имя и почта уже настроены, пропусти этот шаг.

1 - Открой окно ввода команд
В верхнем меню VS Code выбери Terminal → New Terminal / «Терминал» → «Создать терминал». Если Terminal не видно, сначала нажми … в верхнем меню.

2 - Выполни две настройки
Замени Имя Фамилия на своё имя, your-email@example.com — на свою почту. Вставляй команды ниже по одной строке и нажимай Enter после каждой.

3 - Закрой нижнюю панель
Нажми × у нижней панели. Дальнейшие действия выполняются кнопками VS Code и Gitea.

Внизу слева должно быть main. Если там другое имя, нажми на него и выбери main.

2 - Создай ветку
Нажми main внизу слева → Create new branch… / «Создать ветку».

3 - Введи имя
Напиши DEIN-<номер_своей_задачи>-git-practice и нажми Enter. Для задачи DEIN-47 пример — DEIN-47-git-practice. Новое имя появится внизу слева.

DEIN-8695-git-practice

10 - 

Создай файл практики
Нужно добавить один файл: onboarding/guides-practice.txt. Уже существующие файлы проекта оставь как есть.

1 - Создай папку
Слева открой Explorer — первый значок. Наведи указатель на имя проекта → New Folder, значок папки с плюсом → введи onboarding → Enter. Если onboarding уже есть, используй её.

2 - Создай файл
Правая кнопка по onboarding → New File → guides-practice.txt → Enter.

3 - Напиши в файле строку "Практика по гайдам завершена" и сохрани
Впиши строку из блока ниже без кавычек и точки. Нажми Ctrl+S. Внизу справа должна быть кодировка UTF-8.



11 - 

Подготовь изменение к отправке
Сначала выбери файл и напиши, что сделал. В следующем шаге одна команда сохранит коммит и отправит его на Gitea.

1 - Сохрани файл и открой изменения
Нажми Ctrl+S. Слева нажми Source Control — значок с тремя соединёнными точками. Найди guides-practice.txt в Changes / «Изменения».

2 - Подготовь один файл
Нажми + справа от файла. Он перейдёт в Staged Changes / «Подготовленные изменения». Там должен быть только файл практики.

3 - Напиши сообщение
В поле Message над синей кнопкой введи "DEIN-8695 add guides practice". Укажи номер своей Jira-задачи: DEIN-47 на скрине — пример. Пока оставь сообщение в поле и переходи к шагу 12.



12 -

Отправь ветку на Gitea
Commit & Push выполняет два действия: сохраняет подготовленный файл коммитом Git и отправляет изменения твоей ветки на Gitea.

Перед отправкой файл должен быть сохранён (Ctrl+S), в Staged Changes — только файл практики, а в поле Message — описание твоей работы.
Если коммит уже сделан отдельно и подготовленных изменений нет, отправь его через Publish Branch / «Опубликовать ветку» или … → Push. Создавать пустой коммит не нужно.

1 - Раскрой меню кнопки Commit
В Source Control найди синюю кнопку Commit / «Зафиксировать». Нажми маленькую стрелку вниз справа от неё — на скрине показано именно это меню.

2 - Выбери Commit & Push
Нажми «Commit & Push» / «Зафиксировать и отправить» — выделенный пункт на скрине. VS Code сначала создаст коммит с твоим сообщением, затем начнёт отправку ветки.

3 - Подтверди первую публикацию ветки
Если VS Code спросит, нужно ли опубликовать новую ветку (publish this branch), нажми OK / «ОК». Если появится выбор сервера, выбери origin — HTTPS-адрес твоего учебного репозитория Gitea.

3 - Дождись окончания и проверь результат
Если Git запросил учётные данные Gitea, введи учебный логин и пароль (в строке вверху). Дождись завершения отправки без ошибок, открой свой репозиторий Gitea в браузере и обнови страницу. В списке веток должна появиться твоя DEIN-<номер>-git-practice с новым коммитом.



13 - 

Создай запрос на проверку в Gitea
Pull Request (PR), или «запрос на слияние», показывает изменения твоей ветки относительно main. По нему бот проверит практику.

1 - Начни PR
Обнови страницу репозитория Gitea → «Новый запрос на слияние» в сообщении о новой ветке. Если сообщения нет: «Запросы на слияние» → «Новый запрос на слияние».

2 - Проверь ветки
Слева «базовая ветка» — main. Справа «взять из» — твоя DEIN-<номер>-git-practice. Обе в твоём личном репозитории.

3 - Создай PR
Заголовок: «Практика по Jira и Git». Описание: «Добавлен onboarding/guides-practice.txt. Проверены строка и отсутствие других изменений». Нажми «Создать запрос на слияние».



14 - 

Проверь PR и скопируй ссылку
Перед сдачей проверь, что в PR попала только нужная работа.

Оставь PR открытым. Нажимать «Слить» / Merge не нужно. Если сравнение пустое, проверь отправку и выбранные ветки.

1 - Посмотри файл
Во вкладке «Изменённые файлы» / Files Changed должен быть только onboarding/guides-practice.txt со строкой «Практика по гайдам завершена».

2 - Скопируй адрес
Скопируй ссылку из адресной строки браузера. В ней должно быть /pulls/<номер>, например /pulls/1. Ссылка на ветку, файл или Jira для сдачи не подходит.
--
https://gitea.prod.de-infra.ru/de-infrastructure/oleg_sivov-repo/pulls/1/files

15 - 

Отправь PR на автопроверку

Вернись на эту страницу платформы → вкладка «Практика» → форма «Сдай работу через Gitea».

Бот проверяет твой PR, личный репозиторий, отдельную ветку в main, точную строку файла и отсутствие посторонних изменений.

1 - Вставь ссылку
В поле «Ссылка на PR в Gitea» вставь адрес своего PR. В комментарии кратко напиши, что сделал.

2 - Отправь
Нажми «Отправить на проверку». На вкладке «Проверка» появятся результат и замечания.



16 - 

Дождись зачёта и переходи дальше
Принятая Git-практика снимает стартовую блокировку следующих тем. Практика обязательна для новых и текущих учеников.

Jira автоматически не проверяется. Слияние PR не требуется. После зачёта действует обычный порядок обучения.

1 - Если принято
«Принято», «Готово» или «Ок, иди дальше» — это зачёт. Вернись в Jira и переведи тренировочную задачу в «Выполнено».

2 - Если нужны исправления
Исправь файл в той же ветке VS Code. Сохрани Ctrl+S → + у файла → новое сообщение → стрелка справа от Commit → Commit & Push. Повторно отправь тот же PR на платформе.
